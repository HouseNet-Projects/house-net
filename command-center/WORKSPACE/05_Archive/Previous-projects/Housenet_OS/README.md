# Housenet OS

Կազմակերպությունը վարող օպերացիոն շարժիչ. Ամեն օր վերցնում է ձեր տվյալը, կիրառում է
բաժինների կանոնները, և արտադրում է աշխատանքային օրը՝ առաջադրանքներ, ժամկետներ,
ահազանգեր, կալենդար և փաթեթներ։

Շարժիչը **բաժին-անկախ** է։ Ամբողջ բովանդակությունը ապրում է `config/`-ում —
կոդը միայն կիրառում է այն։ Նոր բաժին ավելացնելը նշանակում է նոր YAML ֆայլ, ոչ թե նոր կոդ։

## Ի՞նչ կա ներսում

| | |
|---|---|
| Բաժիններ | 12 — `sales` `marketing` `telesales` `care` `field` `network` `warehouse` `finance` `hr` `legal` `it` `exec` |
| Ռիթմեր | կրկնվող հանդիպումներ և ընթացակարգեր՝ մուտքով, ելքով, տերով |
| Արտադրանք | ժամկետային միավորներ՝ փոստ, վիդեո, հաշվետվություն. ամեն մեկը ծնում է *պատրաստել* + *թողարկել* զույգ |
| Հսկիչներ | շեմային կանոններ մետրիկների վրա → ուղղիչ առաջադրանք տերով |
| Escalation | ուշացած առաջադրանքը ինքն է բարձրանում բաժնի ղեկավարին |

## Տեղադրում

```bash
pip install pyyaml
cd Housenet_OS
python -m housenet_os.cli doctor
```

`doctor`-ը ստուգում է կոնֆիգը և ցույց տալիս չվերագրված դերերը։

## Առաջին գործարկում

```bash
# 1. Լրացրու config/org.yaml — մարդկանց անունները և դերերը
# 2. Ամսվա պլան (առանց անցյալ ամսաթվերի)
python -m housenet_os.cli plan --month 2026-09 --from-today

# 3. Օրվա ցիկլ
python -m housenet_os.cli daily
```

`--from-today`-ն կարևոր է առաջին անգամ. առանց դրա ամսվա սկզբի բոլոր
առաջադրանքները կստեղծվեն և անմիջապես կհայտնվեն «ուշացած» ցուցակում։

## Հրամաններ

| Հրաման | Ինչ է անում |
|---|---|
| `doctor` | Կոնֆիգի ստուգում — դերեր, կանոններ, ամբողջականություն |
| `plan --month YYYY-MM [--from-today]` | Ամսվա բոլոր առաջադրանքների գեներացում |
| `check` | Հսկիչների գործարկում `data/metrics.json`-ի վրա |
| `escalate [--grace N]` | Ուշացածների բարձրացում (կանխադրված՝ 2 օր) |
| `brief [--dept X] [--all-departments]` | Օրվա փաթեթ → `out/` |
| `weekly [--days N]` | Շաբաթվա փաթեթ՝ կատարողականով |
| `tasks [--dept] [--owner] [--overdue]` | Առաջադրանքների ցուցակ |
| `done <id>` / `block <id> <պատճառ>` | Կարգավիճակի փոփոխություն |
| `ics [--dept X]` | Կալենդար → `out/housenet.ics` |
| `status` | Կարճ պատկեր |
| `daily` | `check` + `escalate` + `brief` մեկ հրամանով |

## Ամենօրյա ավտոմատ գործարկում

Windows Task Scheduler, ամեն օր 08:00՝

```
Program:   python
Arguments: -m housenet_os.cli daily --quiet
Start in:  C:\Users\Admin\Desktop\Housenet_OS
```

Ամսվա 1-ին օրը՝ առանձին առաջադրանք `plan` հրամանով։

Կալենդարը՝ `out/housenet.ics`, ներմուծվում է Google Calendar / Outlook։
Ամեն վերագործարկումից հետո ֆայլը թարմացվում է նույն UID-ներով, այնպես որ
իրադարձությունները չեն կրկնվում։

## Կոնֆիգի կառուցվածք

```
config/
  org.yaml              մարդիկ, դերեր, բաժիններ, աշխատանքային օրացույց, տոներ
  targets.yaml          ամսվա թիրախներ
  playbooks/<dept>.yaml բաժնի kpis / rituals / deliverables / controls
```

**Կանոնները հղվում են դերին, ոչ մարդուն.** Մարդը փոխվում է — փոխում ես `roles`-ի
մեկ տողը, և բոլոր առաջադրանքները գնում են նոր տիրոջը։

### Cadence-ի տեսակներ

`daily` · `workdays` · `weekly` (+`weekday`) · `biweekly` · `monthly` (+`day`) ·
`quarterly` (+`months`, `day`) · `month_start` (+`offset`) · `month_end` (+`offset`)

Ամսական և եռամսյակային ամսաթվերը ավտոմատ տեղափոխվում են աշխատանքային օրվա։

## Տվյալի շերտը — ինչ է պակասում

Հսկիչները կարդում են `data/metrics.json`։ Հիմա այնտեղ **նմուշային տվյալ** է
(`_source` դաշտը դա նշում է)։

Իրական տարբերակում այս ֆայլը ամեն առավոտ գեներացվում է CRM/billing/dispatch
API-ներից — դա `it.metrics_pipeline` արտադրանքն է playbook-ում։ Մետրիկների
անունների ամբողջական ցուցակը հենց այդ ֆայլն է. այն ծառայում է որպես
պայմանագիր տվյալի շերտի և շարժիչի միջև։

`check`-ը բացակայող մետրիկը սխալ չի համարում — այն հայտնում է որպես
**տվյալի բաց** և նշում, որ այդ հսկիչը կույր է։ Սա միտումնավոր է. լուռ
անտեսելը ավելի վտանգավոր է, քան բացը ցույց տալը։

## Սահմանափակում, որ արժե իմանալ

Համակարգը լիազորություն չունի մարդկանց վրա։ Այն կարող է առաջադրանք դնել,
հիշեցնել և escalate անել — բայց եթե ղեկավարությունը չի կանգնում դրա հետևում,
երկու շաբաթից բոլորը կանտեսեն։ Այս տիպի համակարգերը մեռնում են այստեղ,
ոչ թե տեխնիկապես։
